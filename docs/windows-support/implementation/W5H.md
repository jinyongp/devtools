# W5H — fixed hosts target and CurrentUser certificate trust

Validation authority is native GitHub Actions on both CPUs. Actual PC UAC dialogs, browser behavior and terminal closure remain NOT RUN, as agreed. No local Windows runtime is used.

The one-shot helper uses a local, first-instance, remote-rejecting named pipe with a protected user/SYSTEM DACL. Only a random pipe name appears in argv. Both peers authenticate held process handles, the same user SID, process ID, and the pinned executable's NTFS identity and SHA-256 before exchanging a bounded, strict JSON frame. The image and its parents must deny modification by unrelated users. Client SQOS permits identification, not impersonation. Parent disconnection cancels received work; the existing operation receipt is reconciled on retry.

The private entrypoint accepts only typed hosts, trust and setup requests. Hosts always means the WindowsDirectory API's System32/drivers/etc/hosts. No request chooses a file path or command. Hosts changes use same-user runas only when interactive and not already elevated. Noninteractive hosts changes require an elevated token. CurrentUser trust uses an ordinary same-user child. Isolated mode rejects shared OS changes before helper launch.

Hosts compares the preview digest against the held original and preserves external bytes and existing newline style. A flushed, closed candidate carries the original owner, group, DACL and SACL, verified before one NTFS POSIX replacement through Go Root.Rename. Required metadata privileges are scoped and restored. Sharing conflicts fail without rewriting the original; stale previews, cancellation, missing privileges, reparses and incompatible ACLs fail closed. No in-place rewrite or power-loss guarantee. A helper crash before publication may retain its unique completed temporary file; there is no broad prefix cleanup.

Trust modifies only CurrentUser Root. A private versioned receipt and a random user-defined certificate property jointly establish ownership. Preexisting certificates are never adopted or removed. Prepared/owned/removing states reconcile lost responses without replacing CA keys. A certificate substituted externally fails ownership checks. The helper receives only public certificate material.

Review ledger (pending until native evidence): IPC identity/SQOS/cancellation; fixed target and strict dispatch; hosts digest/atomic publication/security/newlines; certificate ownership and interrupted operations; private CA storage; isolated callers; native TLS, HTTP/2 and WebSocket; Unix compatibility. Native fixtures restore only their disposable hosts block and uniquely generated test certificates. Tests that mutate the OS require explicit disposable-runner opt-in.

Native feedback: both the logical and system-registry CurrentUser Root providers blocked inside certificate addition on headless runners. The mutation handle now uses the documented registry-backed CryptoAPI provider (`CERT_STORE_PROV_REG`) with the fixed `HKCU\Software\Microsoft\SystemCertificates\Root` key. CryptoAPI duplicates that key handle and persists certificate properties; requests cannot choose a hive/key. There is no root-policy edit, unprotected-store flag, or LocalMachine write. Fresh-process OS chain verification remains mandatory evidence: a registry record that Windows does not trust cannot pass. See [CertOpenStore's registry provider](https://learn.microsoft.com/en-us/windows/win32/api/wincrypt/nf-wincrypt-certopenstore) and [system-store locations](https://learn.microsoft.com/en-us/windows/win32/seccrypto/system-store-locations). Native revalidation is pending.

The hosts original is pinned for reading/security metadata, with deletion sharing but no data-write sharing. Native MoveFileEx replacement failed while that original remained open, so the publication uses Go Root.Rename's NTFS POSIX semantics. The flushed staging file is closed before the rename handle is acquired. Original owner/group/DACL/SACL are explicitly restored on the candidate and checked before publication; a mere inherited descriptor was insufficient on the system hosts fixture. This public-file boundary makes no directory-flush or power-loss promise. The existing private storage SDK still uses its original publication contract. Stage/Win32 diagnostics distinguish permission and publication failures.

The native standard-user fixture uses CreateProcessWithTokenW rather than CreateProcessAsUser, whose additional assignment privilege is absent on hosted runners. This API is test-only. Same-user IPC/SQOS and different-SID/noninteractive fixtures now passed in the focused run; hosts/trust still require correction and revalidation.
