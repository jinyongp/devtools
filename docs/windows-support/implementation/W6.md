# W6 — read-only WSL/platform diagnostics

Implemented `diagnostics.platform` and the public schema, WSL filesystem/interop
fixtures and [the client guide](../../wsl.md). Windows child execution is excluded
from diagnostics. Enabled/absent interop registration remains unknown; explicit
disabled registration is unavailable. Unknown alone does not fail readiness.
Confirmed unsupported private data/config/cache filesystems add a platform issue.
The filesystem field describes the data path; filesystem support alone does not
certify the private ACL/path checks performed by the storage layer.

Windows/WSL data, daemon, CA and ownership remain separate. Bare Linux tool names
never fall back to `.exe`; explicit `.exe` lookup and user WSLENV opt-in are retained.
Managed PE rejection and all existing process ownership contracts remain unchanged.
The public guide separates `.localhost`/custom DNS, IPv4/IPv6/reverse/LAN, and Linux
trust/Windows CurrentUser Root. It exports only the public CA and checks SHA-256
before a deliberate client import. Existing client certificates are not adopted
for removal. Actual Windows manual commands and browser connectivity are NOT RUN.

Validation: Linux full `go test -json -count=1 ./...` (34 package passes, six packages
with no test files, no failed rows), full `go vet ./...`, affected diagnostics and
process race checks, Windows amd64/arm64 cross-build+vet and Darwin arm64 cross-build.
The isolated actual CLI example initialized a CA, exported public PEM, independently
checked its DER SHA-256 against the response, and compared emitted platform fields
to `schema diagnostics`. It reported WSL/ext/interop unknown/ready true. Existing
Linux proxy TLS/HTTP lifecycle and public CA checks passed in the full suite.
No Windows binary, Windows path lookup or Windows browser ran locally. No distro
shutdown, network mode, firewall, portproxy, WSLENV or system PATH was changed.
