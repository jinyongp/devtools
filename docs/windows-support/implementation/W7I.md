# W7I — Windows installer and updater

Task: `fd10b17f-ff86-4876-8279-a2734ec9399d`. Implementation in progress; no completion claim.

PowerShell is a bootstrap downloader/validator. The verified candidate invokes a constrained private installation entrypoint that uses the same Go transaction engine as the Windows updater. This keeps manifest, journal, lock, rollback and ownership decisions in one implementation. PowerShell never changes execution policy or shell profiles, and only an explicit AddToPath changes user PATH.

The engine pins a private local NTFS installation root, holds a stable share-mode-zero install lock, validates manifest file identity/hash and candidate PE/native OS architecture/build identity/runtime version, then journals before staging or moving executable names. Main and an owned alias receive separate candidate copies and unique old-image names. Running images are renamed before replacement. A successful smoke precedes committed state; ordinary failures restore the previous manifest and executable names. Recovery checks actual identities instead of trusting the last persisted phase. Unknown/corrupt state preserves artifacts and fails closed. Busy committed old images are retained for the next invocation. No active daemon is stopped.

A local owned dvt.exe retains ownership even if another dvt is later found on PATH, matching the existing Unix alias policy. A foreign local alias or external dvt prevents alias creation. Updates invoked through dvt.exe still identify the manifest's main executable. No local Windows execution is used; both native Actions CPUs and PS5.1/7 fixtures are required. Physical PC install/update observation remains NOT RUN.

The ARM64 Actions fixture also runs official portable x64 PowerShell 7.6.6 under actual x64 emulation and must still select the ARM64-only release directory. The test fixture is ephemeral, never installed on the host or added to PATH; its SHA-256 is pinned to `02fe458be20493fbdf43f61ea20610b811ee6c738ab1676c61b9cfcd1a33c860`, verified against the [official release asset metadata](https://github.com/PowerShell/PowerShell/releases/tag/v7.6.6). Product installation does not acquire PowerShell or any new runtime dependency. [IsWow64Process2](https://learn.microsoft.com/en-us/windows/win32/api/wow64apiset/nf-wow64apiset-iswow64process2) supplies native OS architecture. PS7's private bootstrap directory uses [FileSystemAclExtensions.Create](https://learn.microsoft.com/en-us/dotnet/api/system.io.filesystemaclextensions.create); PS5 uses Directory.CreateDirectory(path, DirectorySecurity).

Pages checks out the selected release tag and requires each installer that exists in that exact tag to match its release asset. Historical Unix-only tags remain publishable without inventing a Windows installer from main; Windows-capable tags require both assets. Release publication itself is outside this work and is not executed.

Relative Source/BinDir inputs resolve against the PowerShell filesystem location before the native handoff; they do not inherit .NET's potentially different process working directory. Native CLI source paths keep the invoking CLI's cwd. In this intermediate build Windows public version/update/bootstrap are available; other public data/network commands and private daemon entrypoints remain guarded until W7C.
