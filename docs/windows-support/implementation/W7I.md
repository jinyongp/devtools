# W7I — Windows installer and updater

Task: `fd10b17f-ff86-4876-8279-a2734ec9399d`. Scoped implementation and final review complete against definition revision 183. Final product-wide acceptance remains W8A–W9.

PowerShell is a bootstrap downloader/validator. The verified candidate invokes a constrained private installation entrypoint that uses the same Go transaction engine as the Windows updater. This keeps manifest, journal, lock, rollback and ownership decisions in one implementation. PowerShell never changes execution policy or shell profiles, and only an explicit AddToPath changes user PATH.

The engine pins a private local NTFS installation root, holds a stable share-mode-zero install lock, validates manifest file identity/hash and candidate PE/native OS architecture/build identity/runtime version, then journals before staging or moving executable names. Main and an owned alias receive separate candidate copies and unique old-image names. Running images are renamed before replacement. A successful smoke precedes committed state; ordinary failures restore the previous manifest and executable names. Recovery checks actual identities instead of trusting the last persisted phase. Unknown/corrupt state preserves artifacts and fails closed. Busy committed old images are retained for the next invocation. No active daemon is stopped.

A local owned dvt.exe retains ownership even if another dvt is later found on PATH, matching the existing Unix alias policy. A foreign local alias or external dvt prevents alias creation. Updates invoked through dvt.exe still identify the manifest's main executable. No local Windows execution is used; both native Actions CPUs and PS5.1/7 fixtures are required.
